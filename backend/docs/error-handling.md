## エラー分類
エラーを分類すると大きく、業務エラーとシステムエラーの2つに分ける
1. 業務エラー
- 例
  認証失敗、指定されたリソースが見つからないなど想定しうるエラー
- 対応方法
  そのエラーごとに専用のエラーをあげ、`main.py`で受け取っている  
  業務エラーは想定できる具体的な例外のみ捕捉する。Exceptionで一括して捕捉せず、想定外の例外は上位へ伝播させる。


2. システムエラー
- 例
  DB接続が切れた、プログラムのバグなど想定外のエラー
- 対応方法
  main.pyで`Exception`を捕捉して`UNEXPECTED_ERROR`を返すようにしている
  database.py がrollbackし、main.py が500へ変換することを書く

## HTTPステータス使いわけ
基本的には一般的なものと同様に扱っている  
業務エラー発生時は具体的なエラーを表すステータスコードを使用しており、400を使用しない方針である

|     | 用途                                       | 例                                |
| --- | ------------------------------------------ | --------------------------------- |
| 401 | 認証情報がないか無効                       | トークン切れ、トークンなし        |
| 403 | 認証済みだが権限なし                       | 一般ユーザーによる管理者APIの実行 |
| 404 | 指定されたリソースが存在しない             | 活動記録が見つからない            |
| 409 | リソースの競合                             | 完了済み活動の再完了              |
| 422 | 入力の型や構造が不正、ドメインルールが不正 | 必須項目なし、文字列項目に数値    |
| 500 | 想定外のエラー                             | DB接続が切れた、プログラムのバグ  |


## 一括処理時の対処
| 状況                   | ステータス | トランザクション |
| ---------------------- | ---------: | ---------------- |
| 全件成功               |        200 | 成功分をcommit   |
| 部分成功               |        200 | 成功分をcommit   |
| 全件業務エラー         |        200 | commit対象なし   |
| 想定外のシステムエラー |        500 | 全体をrollback   |
